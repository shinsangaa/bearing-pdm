# NASA IMS 실측 RMS 경보 개선·검증

## 적용 파일과 실행

현재 실행 진입점은 `app.py`다. 이 문서는 실측 경보 개선 시 수행한 분석을 보존한 것이며, 파일 정리 후의 경로로 갱신했다. 원본 TXT·전처리 CSV와 경보 계산·FFT 알고리즘은 파일 정리 작업에서 변경하지 않았다.

| 파일 | 역할·변경 이유 |
|---|---|
| `app.py` | Test/Bearing/센서 선택, 원본 CSV 재생, 확정 경보에서 재생 중단·TXT FFT 워터폴, 상태 유지. 조합 표와 전체 시계열 추가. 기본 Chart 화면 |
| `src/ims_alarm.py` | 초기 후보 구간 검증·진단, 단계별 연속 초과·상태 유지, 비교표와 RMS 차트. 판정 함수는 종료 결함 라벨·날짜 규칙을 받지 않음 |
| `src/analyze_ims_alarm.py` | CSV 전용 재현 가능한 전체 조합 분석, 입력 SHA-256 기록, 독립 HTML 생성 |
| `tests/test_ims_alarm.py` | 임계치·연속 조건 경계와 실제 데이터 앱 통합 검증 |

프로젝트 루트 PowerShell:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
.\.venv\Scripts\python.exe -m src.analyze_ims_alarm
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_ims_alarm.py -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## 계산 규칙

센서별 시간순 전체 관측 수의 10%를 올림하고 300개로 제한한다. 이 구간을 정상 **후보**로 고정하며 결측 때문에 뒤의 측정을 가져와 채우지 않는다. RMS가 결측·무한대·음수·0이면 유효하지 않은 관측으로 표시하고 원래 행은 유지한다. 기준 후보에 유효값 10개 이상, 유효 비율 80% 이상을 요구하며 부족하면 계산을 거부한다. 잘못된 시각·중복 시각은 오류를 표시한다.

중앙값 m, 보정 산포 s=max(1.4826×MAD, 0.02×m, 1e-8)로 Warning=m+k×s, Alarm=m+2k×s, Critical=m+3k×s를 계산한다. 기존 산포 하한을 유지했다. 따라서 UI의 “MAD 배수”는 원시 MAD 자체가 아니라 이 보정 산포에 곱하는 k이다. 후보 구간에서 중앙값과의 차이가 6s를 넘는 값은 검토 건수로 출력하고 임의로 제거하지 않는다.

초기·후기 1/3 RMS 중앙값과 변화율을 출력한다. 첫 1/3에서 추정한 같은 방식의 보정 산포 대비 상승 폭이 3을 넘으면 “상승 추세 검토 필요”로 표시한다. 초기 열화뿐 아니라 운전 조건·측정 변화 가능성도 있으므로 이 진단으로 정상/고장을 확정하거나 기준 구간을 자동 교체하지 않는다. 처음부터 일정하게 열화된 상태는 이 진단으로 알아낼 수 없다.

각 단계의 임계값을 **엄격히 초과(>)**하는 연속 횟수를 독립적으로 센다. 기본 재생 조건은 k=5, 3회이며 4·5회도 선택할 수 있다. 단일 피크는 재생 경보·워터폴을 만들지 않는다. 1회 조건은 비교 분석에만 제공한다. 조건을 만족한 N번째 측정을 최초 확정 시각으로 기록하고 첫 초과 시각으로 소급하지 않는다. 유효하지 않은 RMS와 초기 후보 측정 간격 중앙값의 3배를 넘는 공백은 연속 횟수를 초기화한다. 확정된 최대 등급은 낮아지지 않는다. 초기 후보 구간에서는 경보를 판정하지 않는다.

전체 기록은 CSV로 검사하되 화면 재생은 기존처럼 최초 트리거까지 마지막 최대 48개 측정만 보여준다. 4프레임마다 차트를 갱신한다. 워터폴은 조건 충족 이후에만 원본 TXT 최대 16개를 읽는다. RMS와 원본의 센서 매핑 대조, FFT 계산 방식, CSV 캐시, 세션 내 FFT 결과 유지도 보존했다. 앱 재실행 시 저장 결과를 다시 표시하며 TXT를 다시 읽지 않는다. 원본이 없거나 불일치하면 합성 신호를 만들지 않고 오류를 표시한다.

## 실제 데이터 분석

실제 CSV 3개, 센서 16개(첫 시험 8개, 둘째·셋째 각 4개)에 대해 9조합 × 3단계, **432행**을 생성했다. 분석 누락·오류는 없었다. 입력 CSV의 SHA-256을 `ims_alarm_analysis_metadata.json`에 기록했고 분석 후 동일함을 확인했다.

| Test | 센서당 전체 관측 | 실제 기준 후보 | 유효 기준 관측 | 후보 구간 검토 |
|---|---:|---:|---:|---|
| 1st_test | 2,156 | 216 | 216 | 8센서 모두 상승 검토 필요 |
| 2nd_test | 984 | 99 | 99 | 뚜렷한 초기 상승 미검출 |
| 3rd_test | 6,324 | 300 | 300 | 뚜렷한 초기 상승 미검출 |

모든 센서의 전체 RMS에서 결측·0·음수·무한대 건수는 0이었다. 이것이 모든 측정이 정상이라는 의미는 아니다. 첫 시험은 후보 구간 앞·뒤 1/3의 RMS 중앙값이 센서별 14.25~24.87% 상승했다. 일부 센서에서는 전체 후보 중앙값 기준 6산포 초과값도 60~66개 관찰된다. 최초 10%로 늘리는 것만으로 정상성 문제가 해결되지 않는다는 증거다. 날짜를 조정하거나 이 값을 삭제하지 않았다.

아래는 **Alarm 단계** 비교다. 종료 결함 보고 대상은 Test 1 B3/B4의 센서 4개, Test 2 B1 및 Test 3 B3 각 1개로 합계 6센서다. 나머지 10센서는 종료 결함 보고가 없다. 이 구분은 분석 결과 검토에만 사용한다.

지속 조건은 순간 피크를 억제하고 일부 최초 경보를 늦췄지만, 지속적인 공통 RMS 상승은 제거하지 않는다. 높은 배수·긴 지속 조건에서도 종료 결함 무보고 대상에 경보가 남는다. 특히 첫 시험에서는 후보 구간 자체가 변하고, 둘째·셋째 시험의 여러 베어링에서 종료 전 RMS 상승이 관찰된다. 따라서 이 결과만으로 특정 조합의 정확도·오경보율·고장 검출 선행시간을 산정할 수 없고 최적 조합도 확정할 수 없다. 기본 5/3은 재현 가능한 시연 설정이다.

`ims_alarm_comparison.csv`에는 모든 센서·조합·단계의 발생 여부, 최초 **확정** 날짜, 당시 RMS, 임계값, 종료까지 남은 달력 시간, k와 연속 횟수, 기준 구간 검증값이 있다. 경보가 없으면 날짜·RMS·잔여 시간은 빈 값이다. `ims_alarm_summary.csv`에는 모든 단계의 집계가 있으며, `ims_alarm_baseline_checks.csv`는 센서별 초기 후보 진단이다. `ims_alarm_rms_all_combinations.html`은 네트워크 없이 열 수 있는 전체 144개 RMS 차트(센서16 × 조합9)이며, 기준 구간 음영·3단계 임계선·단계별 확정 마커를 포함한다. 앱에서도 선택 조건의 전체 센서 차트를 표시할 수 있다.

**시험 종료 시각은 실제 고장 시작 시각이 아니다.** 종료 결함 무보고를 정상 라벨로 사용하지 않았다. 기존 CSV의 날짜 기반 품질 메타데이터와 RUL·종료 결함 열은 경보 계산에 사용하지 않았다.

## 검증

최신 검증은 `project_structure_verification.json`과 `project_structure_tests.log`에 보관한다. 예전 개발 로그는 정리했다. 경계 시험용 배열은 테스트 함수 내에서만 만들며 실측 재생·분석·FFT 입력을 대체하지 않는다.

경보 전용 테스트는 재생 차트 검증을 포함한 11개이며 전체 프로젝트 테스트에서도 함께 실행한다.

- 단일 피크 차단, 3/4/5번째 측정에서 확정, 단계별 독립 지속 조건, 최대 경보 상태 유지
- 기준 구간 크기·최대 300개·기준 구간 이후 RMS 크기에 대한 임계치 독립성
- 결측/무한대/0/음수/비수치값과 긴 공백의 연속 횟수 초기화, 중복·잘못된 시각 거부
- 초기 상승·극단값 진단, 전체 27행/센서 조합, 확정 시각 기준 잔여 시간
- 실제 Test 2 B1 CSV 재생 → 원본 TXT FFT 생성, 결과 유지 및 rerun 시 원본 재독 방지
- 순간 피크만 있는 시험 입력에서 TXT 읽기를 강제로 차단해도 정상 완료·워터폴 미생성
- Test 변경과 두 센서 선택, 연속 4회 비교 48행, 전체 센서 차트 출력

현재 메뉴와 일치하지 않던 과거 버튼 위치·비활성화 기대값은 현재의 Chart/Home/Logs/User Info 기능을 확인하도록 갱신했다. 세부 실행 결과는 최신 프로젝트 검증 보고서를 참고한다.
